## 一、最终结论

事故根因已经按生产者、契约权威、消费者和运行时四层同时修复：

1. Gateway 三条 sources 生产路径不再发送空数组事件，并以无内容、无标签计数器观测抑制次数。
2. SDK 新增严格四态分类器，成为 `sources` 结构与错误码的公共权威；原 `parseSourcesEvent()` 函数体和宽松行为保持不变。
3. TUI TypeScript 采用新增分类器，空 sources 不下发，损坏 sources 只产生无内容兼容诊断。
4. Rust 将空 sources 固定为 presentation no-op，将展示层损坏固定为 recoverable，将当前回合损坏固定为 `AbortTurn`；只有控制、身份、权限和 framing 安全边界损坏才允许 `FailClosed -> StopRuntime`。
5. shutdown 已幂等，首要错误不会再被 `SDK runtime supervisor is closed` 次生错误覆盖。
6. 63 字节事故帧已在 TypeScript、Rust、运行时和本地发行审计包中回放；连续 100 轮均未触发 runtime stop，最终代码又完成了解压运行与离线安装双路径验证。
7. 回放额外发现并修复了 supervisor Unix socket 路径上限、Memory socket/短目录残留和 macOS 进程扫描复杂度三个深层问题。
8. 开源 TUI 安装包、测试包、构建目录、专属缓存、短 socket 命名空间和相关进程已完成精确清理，复核结果为零。

截图中的 `memory-leader leader busy -> running as follower` 只是选主状态，不是崩溃根因。真正的停机链仍是：

```text
Gateway 发出 sources=[]
  -> TUI TypeScript 绕过 SDK 旧解析器
  -> Rust 把展示零结果错误认定为协议致命
  -> ProjectionEffect::FailClosed
  -> StopRuntime
  -> 整个交互运行环境停止
```

修复后的唯一语义为：

```text
sources=[]                       -> 合法零结果；presentation no-op
sources=[合法非空来源]           -> 保持既有来源展示/活动语义
sources 结构损坏                 -> CompatibilityFault；runtime 存活
消息生命周期损坏                 -> AbortTurn；只结束当前回合
控制/身份/权限/framing 边界损坏  -> FailClosed；允许停止 runtime
```

## 二、为什么修改上游 SDK，以及实际改了什么

### 2.1 修改内容

SDK 仓库：`/Users/fushihua/Desktop/Acosmi/acosmi-sdk-ts`

业务 API 只在 `src/models/types.ts` 做加性扩展：

- 新增 `classifySourcesEvent(ev)`；
- 新增 `SourcesEventParseResult` 四态结果：`not_sources`、`empty_sources`、`sources`、`malformed_sources`；
- 新增八个稳定 `SourcesEventIssueCode`：JSON、数组、item、title、URL、snippet 和 session id 分别有机器码；
- 同时识别 SSE event name 和 JSON payload `type`，兼容两种传输形态；
- 合法事件保留未知额外字段，允许服务端向前扩展；
- 新增独立契约测试、README 与 changelog，版本提升为 `2.15.0`。

没有改变的部分：

- `parseSourcesEvent()` 没有改为调用严格分类器，其历史函数体仍是单独的宽松实现；
- 空数组、非 sources 和 JSON 损坏仍返回 `null`；
- 非空 payload 仍不严格检查 item 字段；
- 返回对象仍精确为 `{ sources, session_id }`，包括 `session_id: undefined` 这个已有 own-property；
- SDK 自己的 `chatStreamWithUsage` 仍调用旧 `parseSourcesEvent()`，现有 SDK consumer 零迁移；
- 未删除、重命名或收窄任何已有导出。

### 2.2 必须由 SDK 定义的原因

`sources=[]` 与“sources 结构损坏”不能继续都折叠成 `null`，否则每个客户端都会自行猜测，正是本次跨语言漂移的来源。SDK 是 SSE event name、payload discriminator 和 `SourcesEvent` 类型三者交汇的最小公共权威层，因此四态和错误码必须在 SDK 定义，而不能复制到每个应用。

这次修改上游 SDK 不是为了强迫所有关联方升级，而是为了提供一个可选择的新严格入口：旧消费者继续使用旧入口，新消费者在需要零结果/损坏区分时采用新入口。这样既消除重复实现，也不把 TUI 的容错策略强加给 Gateway、SDK core 或第三方集成。

### 2.3 关联方兼容矩阵

| 关联方 | 2.15.0 行为 | 兼容结论 |
|---|---|---|
| 既有 `parseSourcesEvent()` 调用方 | 继续走原函数体 | 行为与返回形状不变 |
| SDK `chatStreamWithUsage` | 仍调用旧解析器 | 无需迁移 |
| CrabCode TUI | 显式改用 `classifySourcesEvent()` | 获得四态语义 |
| Gateway | 不依赖 SDK classifier；源头抑制空事件 | 生产者/消费者解耦 |
| 历史会话与第三方 runtime | 即使仍发空或损坏 sources，TUI 防御层也不停止 runtime | 向后回放安全 |
| 未来增加 sources/item 字段 | 严格分类器保留未知字段 | 加性向前兼容 |
| 控制协议关联方 | 不受 sources 展示策略影响 | fail-closed 权威不放宽 |

SDK 兼容测试专门固定了旧入口的宽松“异常”行为，包括非对象 item 和数字 `session_id` 仍被原样返回；这防止严格分类器通过重构意外收窄旧消费者接受范围。

## 六、真实回放发现的深层问题

### 6.1 Supervisor Unix socket 超过 `SUN_LEN`

真实包隔离回放首次暴露：

```text
CRABCODE_PURE_TUI_LAUNCH_FAILED: IPC 服务器启动失败:
path must be shorter than SUN_LEN
```

每轮唯一 `CRABCODE_CONFIG_DIR` 很长，supervisor 原来固定使用 `<state>/supervisor/<pid>.sock`，macOS 内核拒绝过长 UDS 路径。

修复位于 `crates/acosmi-supervisor/src/ipc.rs`：

- 内核可表示的短状态根仍逐字节使用历史路径，避免改变既有关联方。
- 只有过长路径使用 `/tmp/crabcode-supervisor-<122-bit-random>/<pid>.sock`。
- 精确路径继续通过已有 `CRABCODE_SUPERVISOR_UDS` 注入受信子进程，调用方不重新计算、不改 API。
- 私有目录强制并复核 `0700`，socket 强制并复核 `0600`；权限或类型不符立即失败。
- bind、chmod、metadata 或启动失败均清理自己创建的路径；正常 shutdown 删除 socket 与私有目录。

### 6.2 Memory promotion 后 socket 与短目录残留

第二次回放发现 coordinator/child 已退出，但 endpoint pathname 仍存在。修复位于 `libs/acosmi-memory/acosmi-memory-orchestrator/src/lib.rs`：

- `BoundUnixSocketPath` 在 bind 后记录实际 socket 的 device/inode。
- serve 退出时只删除自己绑定的同一 inode；若同用户后继进程替换了 pathname，旧 owner 必须保留 replacement。
- 对内部 `/tmp/crabcode-memory-<32hex>` 命名空间同时记录父目录 device/inode。
- 只有成功删除自己的 socket 且父目录仍是同一私有 `0700` 目录、并且为空时才删除父目录。
- 非空目录、replacement inode、意外内容或身份变化全部保留。

最终 smoke 新增 `memory_namespace_leaks` 硬指标，不再只检查进程和 socket 文件。

### 6.3 macOS 包进程扫描复杂度

旧 smoke 对系统每一个 PID 调用一次 `lsof`，一轮可能耗时数分钟。现改为：

1. 用一次 `ps -axo pid=,comm=` 预筛固定包进程名；
2. 只对候选 PID 调用 `lsof`；
3. 最终权威仍是 canonical executable realpath 必须位于精确 package/install root 内。

清理不会使用 `pkill`、进程名模糊匹配或杀死其他 CrabCode 产品。
