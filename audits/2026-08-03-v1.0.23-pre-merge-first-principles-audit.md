## 一、最终结论

本次崩溃不是安装包损坏、CPU 架构错误、网络中断，也不是截图中的 Memory leader/follower 选举造成。唯一完整因果链是：

```text
Gateway 在 web_search 后发送 sources=[]
  -> TUI TypeScript 因 payload 已带 type=sources 而绕过 SDK 旧解析器
  -> 空数组原样进入 StructuredIO/Rust renderer
  -> Rust 把可选展示事件误判为协议致命错误
  -> ProjectionEffect::FailClosed
  -> StopRuntime / supervisor abort
  -> 整个交互运行环境停止
  -> 退出时二次 shutdown 又以 SupervisorClosed 遮蔽首要原因
```

事故帧由 metadata、固定 envelope、`encoded_len=63` 和截图错误逐项绑定为：

```json
{"type":"stream_event","event":{"type":"sources","sources":[]}}
```

该文本的 UTF-8 长度恰为 63 字节。截图中的：

```text
[memory-leader] leader busy — running as follower; watchdog @ 30000ms
```

是另一个活跃进程持有 Memory 租约时的正常 follower 状态，与 sequence 6034 的 renderer 校验没有调用关系，只是同屏出现的伴随信息。

修复后的唯一处置语义为：

| 输入或边界 | 处置 | 运行时结果 |
|---|---|---|
| `sources=[]` | `presentation_noop` | 不写 transcript、不改变 turn、不停 runtime |
| 合法非空 sources | 正常来源展示 | 保持既有行为 |
| sources 结构损坏 | `recoverable` | 只写无内容兼容诊断 |
| 当前回合消息生命周期损坏 | `AbortTurn` | 结束本回合，下一回合可继续 |
| framing、控制关联、身份、权限或秘密边界损坏 | `FailClosed` | 允许停止 runtime |

## 二、第一性原理复核

### 2.1 进程终止权必须来自安全权威

来源引用是可选展示数据，不授予工具权限、不确认会话身份、不改变控制通道。零来源已经是确定的业务结果，不存在需要通过停止整个 runtime 来消除的不确定性。因此展示事件没有全局终止权；只有安全权威或协议 framing 无法可信判断时才允许 fail-closed。

### 2.2 生产者与消费者必须各自成立

Gateway 不发送无信息的空 sources，减少歧义；SDK/TUI/Rust 仍必须容忍空帧，保护历史会话、旧 Gateway、第三方生产者和未来协议扩展。只改 Gateway 会让历史数据继续崩溃，只改客户端会让错误帧持续扩散；两侧同时修复是必要条件。

### 2.3 契约事实必须只有一个公共权威

事故前，SDK、TUI TypeScript 和 Rust 各自手写 sources 判断并形成相反语义。`@acosmi/sdk-ts` 位于 SSE event name、JSON discriminator 和公开 `SourcesEvent` 类型的交汇处，因此“非 sources、空 sources、合法 sources、损坏 sources”四态必须由 SDK 定义。TUI 只决定产品处置，Rust 只做独立边界防御，不再重复发明业务不变量。

### 2.4 清理错误不得覆盖首要错误

cleanup 是补偿行为。runtime 已停止后再次 shutdown 必须幂等；如果首要 renderer/turn 错误已经存在，清理错误只能作为附加原因。本次同时修复了生产 shutdown 和发布烟测清理的错误优先级，避免 `SupervisorClosed`、`TypeError` 或清理失败遮蔽第一现场。

## 七、发布链深挖发现

复核没有停留在事故表面，又关闭了四个发布链问题：

1. **manifest 排序漂移**：assembler 使用 codepoint，smoke 使用 `localeCompare`，内容完全一致仍会误报。现统一共享 portable comparator。
2. **隔离 HOME 未创建**：仅设置不存在的 HOME/XDG 会让打包运行时在 renderer handshake 前无 stderr 挂起；最小 A/B 复现证明目录存在即通过。现先创建标准目录再启动。
3. **stderr 状态根漂移**：supervisor 曾绕过 `CRABCODE_CONFIG_DIR` 写默认 HOME。现复用统一 resolver，并有串行优先级回归测试。
4. **门禁错误遮蔽**：受限环境的 `ps` 启动失败曾被空 `stderr.trim()` 覆盖成 `TypeError`，cleanup 还可能覆盖 primary error。现保留原始 `EPERM`、附加清理 cause，并保证 scratch root 回收。

另有一次隔离工作树在 assembler 启动前被外部清理流程移除。命令执行前的 `git status` 已显示跟踪文件全部缺失，assembler 源码也只删除受约束的子路径，因此不是 assembler 自删或产品缺陷。修复提交从只读 rollback 仓恢复并逐 hash 核验；含未提交源码的 `CrabCode-TUI-pre-identity-cleanup-20260803` 明确保留，未纳入清理。
