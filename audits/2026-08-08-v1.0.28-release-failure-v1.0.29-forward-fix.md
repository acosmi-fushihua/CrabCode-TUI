## 一、执行结论

`v1.0.28` 不是公开发行版。其签名标签绑定提交
`37daf3c017bc93b03424993c52b05bf034654d2a`，唯一一次 GitHub Actions run
`30866753871` 的结果为：

2. 原生 Intel macOS 完整 runtime 前置验证成功；

4. 五平台构建矩阵全部跳过；
5. publish 跳过，没有 GitHub Release 或资产。

失败门禁的 8 项测试为 2 通过、6 失败。六项失败共享同一个前置条件：旧夹具假设
“Bun 父进程退出后，Bun 后代会继续持有父进程的 stdout/stderr pipe”。该行为在
Unix 本机成立，但 Windows runner 立即得到 EOF，因而 `streamsClosed=true`、延迟
observer lease 为空。后续断言测到的是夹具自身的跨平台差异，不是产品 Rust
launcher 的观察契约。

本轮不放宽 `runProcess()`，也不把 Windows 失败静默跳过。v1.0.29 将旧 Bun/Bun
夹具替换为原生 Rust launcher 夹具：父进程启动同一原生可执行文件作为后代，显式
继承 stdout/stderr，记录 PID、输出契约后退出。这与产品 Rust launcher 的进程模型
同构，并保留全部八条 fail-closed 断言。

按本轮授权边界，候选提交 `d6f8077a0684a8381002f7f8c23cd66ddba880ec`
通过带 `[skip ci]` 的归档合并提交纳入 main；该提交只归档源码，不是发布动作。
没有创建或推送 `v1.0.29` 标签，没有重跑任何历史 workflow，没有触发新的
Actions run，也没有创建 Release。公开发布状态不因本轮源码归档改变。

## 三、根因裁决

### 3.1 被验证的事实

旧 TypeScript 夹具由 Bun 运行，并再次用 `Bun.spawn()` 启动 Bun 后代，随后调用
`process.exit(0)`。Windows 日志证明该后代没有像 Unix 夹具那样继续维持外层读取端：
父进程退出后 stdout/stderr 立即 EOF。

因此，旧夹具只能证明 Unix 上的 Bun/Bun 继承句柄行为，不能代表以下真实链路：

`Bun 验证器 → Rust launcher → 原生 Memory 后代`

### 3.2 不应从失败推出的结论

本次失败没有执行完整 Windows 发布包回放，不能推出：

- v1.0.28 的 observer lease 产品实现无效；
- Rust launcher 的后代不会持有 Windows 管道；
- Memory coordinator 会再次在 runtime replay 前消失；
- `sources: []` presentation no-op 修复回归。

### 3.3 观察器本身的准确边界

observer lease 保留的是 `Bun.Subprocess` 观察对象及其 capture readers，直到 Memory
promotion 与包进程退出完成；它不是一份可独立证明的 Windows Job Object 所有权。
v1.0.29 同步修正了源码注释，避免再把 JavaScript 强引用扩大表述成未经证明的 OS
Job 所有权。真实包的进程存活、Memory IPC、promotion、退出和清理仍分别由既有
包级门禁验证。

## 四、v1.0.29 实施

### 4.1 原生 launcher 夹具

新增 `tests/fixtures/inherited-stdio-process.rs`，并删除不具备跨平台等价性的
`inherited-stdio-process.ts`。原生夹具：

1. 由固定 Rust `1.92.0` 编译；
2. 使用自身可执行文件启动后代，不依赖 shell、Node 或第二层 Bun runtime；
3. 显式将 stdin 设为空，将 stdout/stderr 设为继承；
4. 将后代 PID 写入隔离临时文件；
5. 覆盖 `closed`、`exit`、`hang`、`partial`、`stderr`、`late` 六种模式；
6. 所有输出均显式 flush，不依赖进程退出时的隐式缓冲刷新。

### 4.2 测试与清理

八项断言原样保留其安全语义：

- 完整换行契约可在后代仍持管道时有界返回；
- 即使已经 EOF，调用方仍可显式要求 observer lease；
- 未授权 open pipe、截断 stdout、非空 stderr 均失败；
- 执行与最终化各有独立期限；
- 接纳契约后的任何晚到输出均失败；
- 夹具清理会从所有 scratch root 重新发现 PID，即使主体断言提前失败也不会漏记；
- 终止后主动等待 PID 消失，2 秒后仍存活即使测试失败。

原生可执行文件的首次启动可能受本机安全扫描影响。一次重复验证中，刚编译二进制
在旧 2 秒执行上限内尚未开始输出，随后同一二进制立即正常。这不是 pipe drain
失败。v1.0.29 将普通夹具的进程执行上限放宽到 10 秒、单测总上限放宽到 20 秒，
但关键 `streamDrainTimeoutMs` 与最终化故障注入仍保持 100ms，没有恢复无界等待。

### 4.3 Windows 前置门禁

Windows preflight 在 Bun `1.3.11` 之外新增固定 Rust `1.92.0` 工具链，然后编译并
运行上述原生夹具。该门禁仍位于五平台矩阵之前；失败时矩阵与 publish 继续跳过。
