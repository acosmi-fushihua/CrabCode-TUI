## 一、最终决策

本事故的根因不是网络、安装包、CPU 架构或 memory leader/follower，而是同一个 `sources` 事件在网关、SDK、TUI TypeScript 和 Rust renderer 之间存在相反语义，加上 renderer 把展示层错误升级为全局协议致命错误。

修复后的唯一语义如下：

1. `{"type":"sources","sources":[]}` 是合法的“零引用结果”，处置等级固定为 `presentation-only`，不写 transcript、不推进 spinner、不改变 turn 状态、不弹 fatal modal、不发送 `StopRuntime`。
2. 非空且结构合法的 `sources` 是 `presentation-only` 事件，保持现有来源展示和 direct-query activity 行为。
3. 结构损坏的 `sources` 是 `recoverable` 兼容性错误，只写无内容诊断，不中断 turn，不中断 session，不终止 runtime。
4. 未识别的增量展示事件默认是 `recoverable`；未识别的控制事件仍是 `protocol-fatal`。
5. 已知消息生命周期事件损坏、且当前 turn 已无法可信投影时，处置等级是 `turn-fatal`：终止当前 turn，保留 runtime，完成关联中断后恢复输入。
6. 只有 framing、关联身份、控制协议、权限、工作区信任、秘密边界或安全权威遭破坏时，处置等级才是 `protocol-fatal`，该等级才允许 `StopRuntime`。
7. TypeScript 正常路径过滤空来源，Rust 作为独立防线继续容忍空来源。任何单层修复都不满足完成条件。
8. 网关停止发送空来源事件，但消费者不得依赖网关永远正确；历史会话、第三方 runtime 和旧缓存仍必须安全回放。
9. shutdown 变为幂等操作；首要 renderer fatal 永远是进程主错误，cleanup 错误只能附加，不得覆盖首要根因。
10. 测试全部使用唯一临时状态根并主动回收自己的 daemon；任何测试都不得读取或写入真实 `~/.crabcode`。
11. 发布资产不可覆盖；`v1.0.22` 不再作为回滚目标。候选版失败就阻止稳定版，稳定版回归只发布前滚修复 `v1.0.24`。

## 二、第一性原理与不可变约束

### 2.1 进程存活权属于安全边界，不属于展示事件

来源引用、进度、提示和其他 provenance 数据不会授予权限、不会改变工具执行权威、不会建立会话身份。它们没有终止整个 runtime 的正当性。renderer 必须把“无法展示一项可选信息”和“无法确认协议安全性”分开。

### 2.2 零结果是业务结果，不是协议损坏

搜索可以正常完成但没有引用。数组类型正确且长度为零时，系统已经知道结果是“没有可展示来源”；此时不存在需要 fail-closed 的不确定权威。

### 2.3 生产者与消费者分别负责

生产者不发送无信息帧，减少歧义和带宽；消费者容忍合法空帧和未知可选扩展，防止旧数据、竞态或第三方实现造成停机。两条规则同时成立。

### 2.4 一个事实只有一个权威来源

- `SourcesEvent` 字段结构和分类语义由 `@acosmi/sdk-ts` 定义。
- SSE 名称与 JSON payload 的归一化由 TUI TypeScript adapter 定义。
- 事件处置等级由版本化 policy manifest 定义。
- Rust 事件集合与处置表由生成器产生，禁止维护第二份手写 discriminator allowlist。
- Rust 仍执行边界校验，但不得重新发明比权威分类器更强的业务不变量。

### 2.5 清理不得改变首要故障语义

cleanup 是补偿操作。runtime 已经停止时再次 shutdown 必须成功返回 `AlreadyStopped`；只有运行状态下 supervisor 无预期关闭才是新的 lifecycle 错误。

### 2.6 测试没有访问用户状态的权利

测试必须通过显式依赖注入获得诊断目录和 daemon state root。任何启动 runtime/daemon 或持久化 diagnostics 的 test harness，在 `CRABCODE_CONFIG_DIR` 未指向本次测试临时目录时必须立即失败；纯内存单测使用 no-op recorder，不访问 `HOME`。

## 三、目标事件链路

```text
gateway
  ├─ sources=[]                  -> 不发 SSE；记录无内容计数
  └─ sources=[valid items]       -> 发标准 sources SSE
          ↓
@acosmi/sdk-ts 2.15.0 classifier
  ├─ not_sources                -> 交还普通事件路径
  ├─ empty_sources              -> 明确零结果
  ├─ sources                    -> 交付规范化 SourcesEvent
  └─ malformed_sources          -> 稳定 issue code
          ↓
TUI TypeScript adapter
  ├─ empty_sources              -> undefined + 有界 metadata
  ├─ malformed_sources          -> undefined + compatibility metadata
  └─ sources                    -> canonical stream event
          ↓
Rust projection 防御边界
  ├─ empty sources              -> presentation-only no-op
  ├─ malformed sources          -> recoverable CompatibilityFault
  ├─ malformed turn lifecycle   -> AbortTurn
  └─ protocol/security damage   -> FailClosed -> StopRuntime
          ↓
lifecycle
  ├─ normal/turn-fatal          -> runtime 保持运行，可继续第二轮输入
  └─ protocol-fatal             -> abort；后续 shutdown 幂等且保留 root error
```

| `scripts/generate-renderer-capability-contract.mjs` | 从编译器展开的 TypeScript union 与 policy manifest 生成两个派生文件 |

当前工作区已有未提交的 `scripts/generate-renderer-capability-contract.mjs` 和相关生成文件改动。实施时保留原改动，以其为生成器基线，补入 policy 校验；禁止删除、覆盖或用手写表替代。

生成器必须执行以下拒绝条件：

1. TypeScript union 中有 discriminator 但 policy 未覆盖时退出非零。
2. policy 存在已删除 discriminator 时退出非零。
3. 同一 discriminator 重复或跨分类冲突时退出非零。
4. 生成文件与仓库内容不一致时 `bun run check:capabilities` 退出非零。
5. `sources` 不在编译器展开 union 时退出非零；删除“Rust 独有 extension”特殊豁免。
6. policy 中出现 `pending`、空 owner 或未知 disposition 时退出非零。

### 4.2 固定处置等级

| 等级 | 触发边界 | 运行时行为 |
|---|---|---|
| `presentation-only` | 合法可选展示、provenance、heartbeat/no-op | 记录 raw envelope；按事件展示或 no-op；不改变 runtime/turn 权威 |
| `recoverable` | 可选展示字段损坏、未知增量展示事件、前向兼容扩展 | 产生有界 `CompatibilityFault`；不写伪造 transcript；继续当前 turn |
| `turn-fatal` | 已知 message/content/result 生命周期损坏，当前 turn 无法可信投影，但会话身份和控制通道仍可信 | 发送关联 `Interrupt`；标记当前 turn 失败；收到 ack/result 后清空 active turn 并解锁输入 |
| `protocol-fatal` | StructuredIO 行 framing/顶层 JSON envelope/大小边界损坏；control request/response 无法关联；跨 session/correlation 身份冲突；权限、工作区信任、秘密或私有 runtime 权威损坏 | 锁输入、持久化 root diagnostic、`StopRuntime`、幂等收尾 |

固定默认规则：

- 未知顶层业务/stream discriminator：`recoverable`。
- 未知 control discriminator：`protocol-fatal`。
- 已知 stream event 缺少字符串 `type`：`turn-fatal`。
- SDK SSE data 的普通事件 JSON 损坏：`turn-fatal`；SSE 名称明确为 `sources` 时按 `malformed_sources/invalid_json` 降级为 `recoverable`。
- `message_start`、`message_delta`、`message_stop`、`content_block_start`、`content_block_delta`、`content_block_stop`：合法时按现有 projection 执行，结构或顺序损坏时固定为 `turn-fatal`。
- 明确上游 `error` event：`turn-fatal`，错误只作用于当前 turn。
- `ping`：`presentation-only`。
- `sources`：`presentation-only`；其字段损坏降级为 `recoverable`。
- 未知额外字段：允许并保留，不因字段增加触发错误。

### 4.3 `sources` 精确字段规则

TUI 规范化后的 canonical 结构如下；其中 `sources`、`session_id` 和 item 字段直接来自 SDK `SourcesEvent`，`type` 是 TUI transport discriminator：

```ts
interface SourcesEvent {
  type: 'sources'
  sources: Array<{
    title: string
    url: string
    snippet?: string
  }>
  session_id?: string
}
```

处置规则：

| 输入 | SDK 分类 | TS 行为 | Rust 防御行为 |
|---|---|---|---|
| 不是 sources | `not_sources` | 原普通事件路径 | 按自身事件 policy |
| `sources: []` | `empty_sources` | 返回 `undefined` | 若直接到达则 no-op |
| 非空且字段合法 | `sources` | 发 canonical event | 保持现有 null-render/source activity 行为 |
| 缺少 `sources` | `malformed_sources/missing_sources` | 丢弃该事件并记 metadata | `CompatibilityFault` |
| `sources` 非数组 | `malformed_sources/sources_not_array` | 同上 | `CompatibilityFault` |
| item 非对象 | `malformed_sources/source_not_object` | 同上 | `CompatibilityFault` |
| `title`/`url` 非字符串 | 对应稳定 issue code | 同上 | `CompatibilityFault` |
| `snippet` 存在但非字符串 | `source_snippet_invalid` | 同上 | `CompatibilityFault` |
| `session_id` 存在但非字符串 | `session_id_invalid` | 同上 | `CompatibilityFault` |
| 任意未知额外字段 | 保持合法分类 | 保留 | 保留 |

`sources=[]` 的 no-op 不得推进 direct-query activity、spinner、TTFT、token 统计或 turn completion。

### WP-04：Rust renderer 分级处置

必须修改 `crates/crabcode-tui/src/sdk_projection.rs`、`tui_app.rs`、`lib.rs` 和生成契约。

新增 effect：

```rust
ProjectionEffect::CompatibilityFault {
    sequence: u64,
    event_type: String,
    code: String,
}

ProjectionEffect::AbortTurn {
    sequence: u64,
    code: String,
    reason: String,
}
```

实现规则：

1. envelope framing、sequence/correlation/session 权威先独立校验；该层失败仍返回 `FailClosed`。
2. event discriminator 的 disposition 从生成表读取。
3. `validate_stream_sources_event` 改为分类结果：`Empty`、`Valid`、`Malformed(code)`。
4. `Empty` 返回无 effect，不推进 activity，不创建 UI message。
5. `Valid` 保持当前非空来源行为。
6. `Malformed` 返回 `CompatibilityFault`，保留 raw envelope 与 metadata，不创建 UI message。
7. `CompatibilityFault` 在 `TuiApp` 中只记诊断并继续，不生成 `HostAction`。
8. `AbortTurn` 在 `TuiApp` 中进入 `turn_aborting` 状态并发送现有 `HostAction::Interrupt`，关联目标固定为当前 active turn。
9. 收到关联 interrupt ack/result 后，将 UI turn 状态置为 failed、清除 active turn、解锁输入；失败信息只显示在状态区，不伪造 assistant transcript。
10. 关联中断 5 秒内未收到 ack/result时，控制通道被判定失效，升级为 `protocol-fatal`。
11. 只有 `FailClosed` 创建 `HostAction::StopRuntime`。
12. 未知普通 stream event 产生 `CompatibilityFault/unknown_stream_event`，未知 control event 产生 `FailClosed/unknown_control_event`。

必须删除或重写的错误测试契约：

- 删除 `sources=[]` 属于 malformed 并应 fail-closed 的断言。
- 将 malformed sources 从 `FailClosed` 断言改为 `CompatibilityFault`。
- 删除 `sources` 是 Rust 唯一 runtime extension 的特殊断言。

### WP-05：runtime shutdown 幂等与错误优先级

必须修改 `crates/crabcode-tui/src/sdk_runtime.rs` 和 `crates/crabcode-tui/src/lib.rs`。

新增明确状态和结果：

```rust
enum ShutdownOutcome {
    Graceful,
    AlreadyStopped,
}
```

固定状态行为：

| shutdown 调用前状态 | 行为 | 结果 |
|---|---|---|
| Running 且 supervisor 活跃 | 发 Shutdown、关闭 transport、join | `Graceful` |
| Aborting | 完成 join；sender 已关闭视为预期 | `AlreadyStopped` |
| Stopped | 不再次发送命令 | `AlreadyStopped` |
| Running 但 supervisor 无先前 abort 就关闭 | 保留 lifecycle 失败 | `SupervisorClosed` error |

主流程错误组合规则：

1. 先保存 `pre_shutdown_failure`。
2. 无论 execution outcome 如何都执行一次幂等 shutdown。
3. 存在 `pre_shutdown_failure` 时，以它作为顶层 error；shutdown error 只附加到 error chain 和 diagnostic。
4. 不存在首要错误时，意外 shutdown error 才成为顶层 error。
5. panic 路径完成有界收尾后恢复原 panic payload，不用 cleanup panic 替换它。

### WP-06：诊断隔离与可复现证据

必须修改 `crates/crabcode-tui/src/renderer_diagnostics.rs` 及 production wiring。

结构决策：

1. 删除 `OnceLock<Option<Mutex<DiagnosticSink>>>` 环境全局单例。
2. `Projection::default()` 使用明确 no-op recorder。
3. production 入口从 `acosmi_daemon_launcher::paths::home_dir()` 取得已尊重 `CRABCODE_CONFIG_DIR`/`CRABCODE_HOME` 的 state root，并显式注入 recorder。
4. 单元和集成测试只能注入 `tempfile::TempDir` 下 recorder。
5. recorder 保持 8 MiB 有界轮转；raw dump 继续仅在显式 opt-in 时启用。

每条 compatibility/fatal metadata 固定包含：

- `sequence`
- `envelope_type`
- `stream_event_type`
- `disposition`
- `issue_code`
- `encoded_len`
- 已知字段存在位图
- 未知字段数量；未知字段名不落盘
- 各顶层数组长度
- `schema_version`
- type-only canonical shape 的 SHA-256；所有未知 key 统一替换成 `$unknown` 后再哈希
- root error chain 的稳定 code

明确禁止写入：prompt、tool input/output、query、title、URL、snippet、token、密钥、cookie、完整 session 内容。

### WP-07：测试状态根与 daemon 回收

生产 memory coordinator 的“稳定驻留、leader/follower、跨 TUI 生命周期”行为保持不变。本工作包只改测试 harness。

`scripts/release-package-smoke.mjs` 必须执行：

1. 为每次运行创建唯一临时解包目录和唯一 `CRABCODE_CONFIG_DIR`。
2. 启动前对真实状态根的目录条目、文件 size/mtime 和内容哈希建立 sentinel。
3. 从发布包内 launcher 启动完整 TUI 和 memory coordinator，不引用工作区二进制。
4. 回放 sequence 6034 的 63 字节事故 frame。
5. 继续发送合法 text/result，完成第一轮，再提交第二轮输入并得到成功结果。
6. 在 `finally` 中向该临时 endpoint 发送现有 `memory.coordinator.promote`，successor build 固定为 `2.0.0+release-smoke-cleanup`，协议/schema 与运行实例一致。
7. 最长等待 10 秒，确认 coordinator、serving child、owner lock 和 socket 全部消失。
8. 超时即保持测试失败，并只按“PID 已记录且 executable realpath 位于本次解包根内”双条件终止残留；禁止 `pkill crabcode`、名称通配和影响桌面版。
9. 删除本次临时根；再次核对真实状态 sentinel 逐项一致。
10. 退出后扫描进程，来自本次发布包路径的进程数量必须为零。

测试不得新增生产 `shutdown` IPC；回收使用现有 promotion 机制，避免扩大未认证控制面。

5. 兼容性的 curl pipeline 保留执行能力，但 installer 首行明确提示“bootstrap 未验证来源”；文档不再推荐该入口。
6. `v1.0.22` release notes 增加 P1 known issue，明确升级到 `v1.0.23`，不得删除或覆盖 v1.0.22 资产。

## 八、实施与发布顺序

顺序不可交换：

1. **保护现有用户**：合并并全量部署 WP-01；验证生产计数只出现 suppressed-empty，不再出现下游空 sources frame。
2. **建立权威分类**：合并 WP-02，发布不可变 npm 版本 `2.15.0`，验证 registry tarball 的导出和 integrity。
3. **落实统一契约**：在 TUI 合并 policy manifest、生成器和 normalized union，删除 sources 特殊豁免。
4. **修复双层消费者**：同一 TUI PR 合入 WP-03 与 WP-04，精确固定 SDK 2.15.0。
5. **修复错误与收尾语义**：同一 TUI PR 合入 WP-05 与 WP-06。
6. **封闭测试环境**：同一 TUI PR 合入 WP-07、全测试矩阵和 fixture。
7. **封闭发布链**：同一 TUI PR 合入 WP-08、WP-09 和 release workflow 门禁。
8. **候选发布**：提交仅包含版本/changelog 的 RC identity commit，将 package version 设为 `1.0.23-rc.1`；创建签名 tag `v1.0.23-rc.1`，生成五个平台包，完成每平台 100 次 package replay。
9. **24 小时 soak**：五个平台各完成 100 个真实交互 session，共 500 个 session；每个 session 包含 web search 零来源、非空来源、普通文本、interrupt 和第二轮继续。
10. **稳定发布**：所有硬指标为零错误后提交仅包含版本/changelog 的 stable identity commit，将 package version 设为 `1.0.23`；创建新的签名 tag `v1.0.23`，重新从 tag 构建、测试、attest，draft 验证完成后标记 latest。
11. **发布后 72 小时强化值守**：支持方每 4 小时检查 GitHub issue 和公开错误报告；任何相同 fingerprint 立即阻止后续推广并启动 `v1.0.24` 前滚修复。

## 十、失败处置与前滚策略
